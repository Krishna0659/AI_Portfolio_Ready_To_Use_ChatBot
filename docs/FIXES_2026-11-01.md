# Theme, uploads and failed imports

## Diagnosed causes

- Theme was applied only to the future-widget preview, not the application shell.
- React reconciled the controlled URL input and uncontrolled file input as the same element when changing import tabs.
- Duplicate source validation checked source existence without considering the latest import outcome.
- The failed source was Krishna0659/Text-Summazrizer. GitHub returned HTTP 403 with `x-ratelimit-remaining: 0` and an API-quota error, not a document parser or repository-duplication error. PaySure's earlier import remained successful.

## Changes

- Whole-workspace light/dark/system semantic colors; immediate theme preview, database persistence on Save settings and OS-preference listener.
- Separate keyed URL/file inputs, file-state reset on tab changes and after completed upload. No controlled/uncontrolled warnings during browser regression.
- Re-submitting a failed/cancelled existing source queues a retry using the same ID. Existing running/ready sources are selected with status-specific explanatory copy instead of rejected.
- Typed upstream errors separate quota exhaustion, access denial, missing source and transient server failures. Shared GitHub cooldowns persist in PostgreSQL; retry timing respects reset/retry-after headers and automatic attempts are bounded. No access restriction is bypassed.
- Evidence panel shows the latest error even if an older successful capture exists. Successful evidence is retained and not misrepresented as a new capture.
- Added line-level comparison between the latest two successful captures. This does not overwrite profile edits or replace the remaining three-way profile conflict-resolution work.
- Approval checks only each active source's latest job; an old failed attempt no longer blocks a later successful retry.

## Executed verification

- 13 Node tests passed (including real PostgreSQL RLS and new retry/diff tests).
- 10 API workflow checks passed.
- Seven browser regression checks passed; no browser console errors: dark rendering, persistence, system-change response, light restoration, repeated upload-tab switches, cleared file selection, failed-source deduplication/retry.
- TypeScript and production build passed.
- Retried the actual failed source through the application. It entered a persisted queued state with a clear quota explanation and provider-supplied next attempt of 7:53 PM IST on 1 November 2026. Its subsequent successful import has not yet been verified; the external API quota remains authoritative.
